# Full improvement review of soiree, September 2026

The pass that [the September review](2026-09-19-review.md) designed but could
not run. It ran on 2026-09-20 against `bbbeec1`, driven by
[`.claude/workflows/soiree-improvement-review.js`](../../.claude/workflows/soiree-improvement-review.js),
and this is the report it produced.

## What ran

Thirteen reviewers each read one dimension of the code and returned findings
with file and line evidence. Every finding then went to two independent
skeptics, one asked whether it is true of the code and one asked whether it is
worth doing given the decisions in [architecture.md](../architecture.md). A
critic read what the thirteen had covered and named four gaps, which were
reviewed the same way. An editor merged the survivors into the report below.

| | |
|---|---|
| Agent runs | 395, none failed |
| Findings | 188 |
| Confirmed by both skeptics | 183 |
| Refuted on the facts | 0 |
| Refuted on value | 5 |
| Unverified | 0 |

The four gaps the critic found were the planner's accessibility and rendered
behaviour, the outbound mail and push messages, the spreadsheet importer, and
the upgrade, rollback and version-skew path. Together they produced 45 further
findings, all confirmed, including two of the three wrong-number bugs in
`soiree-import`.

## How to read "0 refuted on the facts"

It does not mean there was no noise. A skeptic that found a claim partly right
was asked to pass it and write the accurate version into a correction, so the
noise is in the corrections rather than in a refuted list. All 376 verdicts
carry one. The facts skeptics lowered the severity of 19 findings and raised
none:

| Reviewer said | Skeptic settled on | Findings |
|---|---|---|
| high | high | 6 |
| high | medium | 5 |
| medium | medium | 83 |
| medium | low | 14 |
| low | low | 80 |

So every item below is worth re-verifying against the code before acting on it.
Of the first six items acted on, one item's four findings held, and the change
written for them introduced two new defects that a further review caught, which
is the rate to expect.

Findings are 76 bugs and 112 improvements; 148 are small, 37 medium, 3 large.
44 declare a conflict with a decision that is written down, and each of those
says why it is still worth doing. Those are not acted on without the maintainer
deciding.

## Where it stands

The server side is careful: revisions with 409s, an append-only change log,
strict decoding, real-Postgres tests, signed releases. The review found no way
to read or change a plan without a session. The real weakness is the sync layer
in `web/src/app.js`. The shadow lives only in memory, so the page's promise
that unsent edits "are safe in this browser" is false across a reload, and
several merge branches contradict each other with no test below a full
Playwright run. The second weakness is that unattended pieces fail quietly: a
lost digest, a release signed from a red commit, and an erasure that cannot
reach `change_log` each leave at most a log line. The third is prose written
before 1.0.0, SECURITY.md above all, that now says the opposite of the code.
Most fixes are small, and both high ones sit behind the Store seam.

## Fix now

1. **Unsent edits do not survive a reload or a discarded tab (high).** `dirty`,
   the shadow and `idMap` are in-memory (`web/src/app.js:941-943`), so the next
   load's `adopt()` replaces the cached copy (`app.js:1907-1915`) while
   `d.offline` and `d.session` (`app.js:271,274`) say the edits are safe.
   Persist `{state, shadow, idMap}` in the one `soiree.v1` value at every
   shadow advance, set `dirty` at startup when `planOps()` against it is
   non-empty, and merge through `applyPlan`. Add the abort, edit, reload,
   restore case to `e2e/tests/api.spec.js`; until it ships, reword the two
   strings.

2. **A page opened while the origin is unreachable stays local-only for life
   (high).** `connect()` stops after attempt 4 with no notice
   (`app.js:1622-1627`) and `Sync.push` is inert without `apiMode`, so the
   edits then fall into item 1. Keep retrying at `RETRY_MAX_MS` on status 0 or
   5xx and on `online`, and show `d.offline` when the cached copy holds
   `SERVER_ID` rows; 200, 401 and 404 stay final. Same root: `probeSession()`
   latches "out" on 0/5xx (`web/src/auth.js:1057-1075`), so a viewer gets no
   lock; re-ask with the same backoff.

3. **A database blip signs everybody out (medium).** `Authenticate` clears the
   cookie on any `SessionByToken` error, not only `ErrNotFound`
   (`internal/httpd/authmw.go:51-62`), which breaks "an outage is not a
   sign-out" (`docs/architecture.md:229`). Clear only on `ErrNotFound`;
   otherwise mark the context and let the `Require*` guards answer 503 with
   `Retry-After`; stay quiet on `context.Canceled`. Test with a closed pool.

4. **POST creates are not idempotent (medium).** A create whose 201 is lost is
   re-sent and the line counts twice in every total
   (`internal/httpd/api.go:219-234`, `app.js:1384-1411`). Keep `uid()` and
   `adoptServerId`; give each new row a persisted client-minted uuid sent as
   `id` on create only, and on a 23505 against the table's pkey answer 200 with
   the stored row.

5. **Numbers the column cannot hold (medium).** `qty >= 1e9` or a NUL in text
   falls through `constraintError` to a 500 (`api.go:435-444`,
   `api_entities.go:87`), which the page retries forever and which blocks later
   writes. A value with excess decimals is rounded by the column, never equals
   the shadow, and re-PATCHes 8 times per 30 s (`app.js:985-992`); each no-op
   bumps the revision unannounced (`internal/store/audit.go:401`). Map SQLSTATE
   class 22 to 400, bound and scale-check `qty` like `setRate`, give
   `numberField` a scale, roll back an UPDATE whose diff is empty, and set
   `rateInput` to `min="0" step="any"` (`web/src/index.html:268`).

6. **`updated_by` is NULL for every API write (medium).** The eight write
   statements bind the legacy `actor` argument, always nil from
   `api_entities.go:124-299`, instead of `who.ID`
   (`internal/store/tasks.go:48,76`, `sponsors.go:35,63`, `phases.go:39,69`,
   `budgetitems.go:66,139`). Each UPDATE wipes earlier values and
   `MatchUpdatedBy` in `privacy.go` never matches. Bind `who.ID`, assert the
   value in an httpd test, optionally backfill from `change_log` as 0009 did.

7. **Two merge rules contradict each other (medium).** A 404 flashes "your copy
   is still here" (`app.js:1404-1408`), then the resync's `applyPlan` filter
   drops the row (`app.js:2152-2156`) and leaves a phantom `blocked` key in
   `unsentCount`. A same-field collision overwrites the other person and
   flashes "both kept" (`app.js:1440-1451`). Keep rows with local
   `changedFields`, park them as a create, prune `blocked`; merge `idsField` as
   a set in `reconcile()` and `applyPlan()`; use another string for scalar
   collisions. No test executes `d.gone`, `d.overtaken` or `d.refused`.

8. **Typed amounts parse by the browser's UI language (medium).** `<input
   type=number>` turns `750.000` into 750 and `45,50` into 4550 with nothing
   flagged (`app.js:4048-4065`); the IDR deployment hits the grouping case. Use
   `type="text" inputmode="decimal"` with one `parseAmount(text, places)` that
   refuses ambiguity and reformats on blur. This also removes the false invalid
   state `step="1"` puts on cents.

9. **soiree-import can emit a wrong budget with a clean report (medium).** The
   sum check adds a flagged subtotal to `runningSum`, so a sectioned sheet
   imports at about 3x (`internal/sheetimport/convert.go:248-254`).
   `ParseNumber` reads `12.03.2026` as 12032026, `2 x 500` as 2500, and drops a
   U+2212 or trailing minus (`number.go:98-125,181-184`). `-detect` discards
   the note for blocks it cannot name (`detect.go:48-55`), and `total/qty`
   emits an unrounded unit the page rounds (`convert.go:214`). Keep section and
   grand accumulators, validate group shape, refuse rather than trim, report
   rows outside every table, warn when a stated total will not survive.

10. **Reset and rate-limit gaps (medium).** `password-reset` has only a per-IP
    bucket, and without SMTP it still supersedes the hand-delivered invitation
    and discards the new link (`internal/httpd/auth.go:489-511`). `clientIP`
    reads the first `X-Forwarded-For` line and keys IPv6 per /128; `sweep()`
    does not bound the map (`ratelimit.go:84-121`). Return early when `a.mailer
    == nil`, add a `resetAcct` bucket keyed on `user.ID`, key IPv6 on the /64,
    evict rather than refuse at `maxKeys`, reject addresses over 254 bytes, add
    `ratelimit_test.go`.

11. **Writes rely on SameSite=Lax alone (medium).** A same-site sibling origin
    can form-post `text/plain` JSON to `POST /api/v1/users` (`server.go:268`,
    `auth.go:1107-1114`). Wrap the mux in `http.NewCrossOriginProtection()`
    inside `instrument`, answer 403 `cross_origin`, add the code to
    `api/openapi.yaml`.

12. **A passkey added from a borrowed session survives a password reset
    (medium).** Only its owner can remove it
    (`internal/store/passwordtokens.go:151-158`, `passkeys.go:164-183`). Add
    admin-only `POST /api/v1/users/{id}/revoke-credentials` deleting sessions,
    passkeys, challenges and tokens in one transaction; say on the set-password
    success screen how many passkeys remain.

13. **Releases are not gated on CI (medium).** `image` needs only
    `release-please` (`.github/workflows/release-please.yaml:38-40`), tag runs
    skip every check, main has no ruleset; v1.1.0 and v1.2.1 were signed from
    red commits. Move the check jobs into a reusable `checks.yaml` that `image`
    and `release-image` need, keep signing where it is, then add rulesets. Fix
    the two flakes first: `e2e/tests/api.spec.js:289` races the 400 ms resync
    (remove `window.EventSource` in that spec, add the silent-merge sibling),
    and `internal/s3test` trusts `/minio/health/ready` (poll a signed HEAD
    instead).

14. **Destructive clicks with no guard (medium).** Removing a line or task
    cascades its attachments unconfirmed (`app.js:4107-4113`,
    `migrations/0012:26-27`), and Import replaces the plan for everyone behind
    one generic confirm (`app.js:4429-4450`). Confirm only when files or
    attributions go; in API mode count removed rows and files, say "for
    everyone", and trigger Export first.

15. **Digest reliability (medium).** A failed run is never retried inside its
    period although `ledger.go:183-185` promises it
    (`internal/reminders/reminders.go:149-160`); one refused RCPT cancels the
    mail for everybody (`internal/mailer/smtp.go:147-151`); overdue rows are
    reported for ever after the event (`digest.go:132-139`). Let `RunOnce` say
    when a retry is useful, send one message per recipient under the single
    claim, skip rows dated on or before the event day once it has passed, and
    dedup on `mail.ParseAddress(addr).Address`.

## Structural

**Make the sync core testable.** Extract `mergeFields(fields, mine, base,
theirs)`, the field factories and the money helpers between markers, call it
from `reconcile()`, `applyPlan()` and the settings merge, and table-test the
slice the way `e2e/tests/auth-ui.spec.js:606` already does. First step: the
three missing conflict specs, with no production change. ES modules are
feasible (rewrite specifiers in `assets.go:185`, or serve one hashed directory)
but only pay for sync and money. Also turn the startup IIFE into `normalise(s)`
used by import too (`app.js:890, 4442`), minting ids for all four collections,
and add a Go test for i18n subsets and the `MINOR_UNIT_EXPONENT` mirror with
`c.item` allowlisted.

**Finish data protection before wiring it.** `privacy.go` predates
`change_log`, attachments, passkeys and push, and the 0007 trigger blocks
redaction even by hand. First step: delete the false caveat at `privacy.go:661`
and the "hard part is built" text. Then a migration allowing one GUC-gated
redaction, erase by key, NOTIFY without `recordUpdate`, purge that covers
`change_log`, and a `soiree privacy` subcommand; the same dispatcher gives
`soiree vapid-keys`. Add `pristine` to `GET /plan` first, or a stale browser
re-seeds a purged plan (`app.js:1895`).

**Observability for what fails silently.**
`soiree_reminder_runs_total{outcome}` and `last_run_ok`, a listener-connected
gauge in `changeHub`, fixed labels for auth, users, attachments, push, activity
(`metrics.go:144`), no histogram for `api-events`, Info lines for refused
logins and link issuance with `by=`, and `writeInternal(w, r, err)` answering
499 on client cancel. First step: the digest series.

**CSP from the binary.** Emit the deployed policy in `securityHeaders`
(`server.go:314`) with `connect-src` from `objstore.Origin()`,
`SOIREE_CSP=off`, no HSTS; fail e2e on `securitypolicyviolation`. The
bucket-drift benefit arrives only when gitops drops `middleware-csp.yaml`.

**Tell an open planner about a deploy.** A `hello` frame with a build id on SSE
connect (`sse.go:475`); on mismatch call `reg.update()` and show "reload when
done". Fail a service worker update whose precache failed (`web/src/sw.js:26`).
One visibility/`online` handler calling `applyMode()` and `scheduleResync()`.

**Upgrade, rollback, restore.** Write the procedure in `docs/operating.md` and
the expand-only migration rule in CONTRIBUTING; warn when the schema is ahead
of the binary (`migrate.go:111`); pin released migration checksums in a
`-short` test with `*.sql eol=lf`; document `DELETE FROM sessions` and "Export
from a browser first" for restores; `stop()` after the first signal, a
WaitGroup on `Auth.background`, a preStop sleep.

**CI and supply chain.** Pin golangci-lint and the builder image by digest
(`Dockerfile:3`), Renovate managers for both and redocly, `minimumReleaseAge`
for gomod and npm, test-only modules as `chore`, merge commits off (changelog
doubling), weekly `govulncheck -mode=binary` on the released image, no gha
cache in signing jobs, OCI labels and `/licenses`, smoke the image with
Postgres and `SOIREE_REMINDER_TZ`, fail CI when backends are missing, count
compressions instead of timing them (`assets_cache_test.go:59`).

**API.** Gzip `GET /plan` and `/activity` only (`api.go:465`); `entity` and
`entityId` filters on `/activity`; document that an omitted `position` is 0.

**Accessibility pass.** Focus after delete and add in the four lists and People
(first field of the next row, never its delete button), focus and `role=status`
on route change, a `forced-colors` block, in-place upload progress,
`#runupFrom` hidden from AT, a "late" word, `table.tasks` unwound for phones.

## Considered and set aside

- Pool-size knob and pooled `statement_timeout`: four connections are ample,
  and the timeout would kill the migration advisory-lock wait.
- Stripping comments from JS and CSS at startup: scripts are deferred and
  precached; a hand-written JS lexer risks a blank page.
- ETag/304 for the second plan read on load: off the interaction path, and
  `max(change_log.id)` is an unsound version.
- Parallel brotli or `FreeOSMemory` at boot: hidden under the 2 s readiness
  delay, and it slows the httpd tests.
- `pgx.Batch` in `LoadPlan`: in-cluster milliseconds for a second scan path.
- Dropped from confirmed items: a `payments` table, a stdlib `.xlsx` reader, a
  per-sponsor statement, a sessions list, step-up re-authentication, HSTS from
  the binary.
